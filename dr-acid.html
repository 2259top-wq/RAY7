ACID = Atomicity + Consistency + Isolation + Durability
01 — 白話直覺

ACID：保證資料「不會出包」的四個承諾

當很多人同時改同一份資料（如轉帳），怎麼確保不出錯？資料庫用 ACID 四大保證。用「銀行轉帳」最好懂：A 帳戶扣 1000、B 帳戶加 1000，這兩步必須一起成功或一起失敗，不能只做一半。

A 原子性Atomicity：一組操作「全做或全不做」，不會只扣款不入帳。
C 一致性Consistency：交易前後資料都符合規則（總額守恆）。
I 隔離性Isolation：多筆交易同時跑，互不干擾，像各自排隊。
D 持久性Durability：一旦完成就永久保存，斷電也不丟。

另外 Schema（綱要）對齊也很重要：不同來源的「日期格式、單位、欄位名」要統一，否則合併資料就會錯亂。

03 — 要點

ACID 與 Schema 對齊

優點

  • ACID 保證交易正確，金融系統必備
  • Schema 對齊讓多來源資料能正確合併
  • 統一時區、單位、命名規範

缺點 / 限制

  • NoSQL 為了效能常犧牲強一致性
  • Schema 不一致 → 合併出現亂碼/錯位
  • 時區沒對齊 → 時間分析全錯

04 — 速記與對照

ACID 四性質

性質意思白話
Atomicity 原子性交易全成或全不成轉帳兩步要嘛都做要嘛都不做
Consistency 一致性交易前後符合規則約束不會出現負餘額等違規狀態
Isolation 隔離性併發交易互不干擾同時操作像排隊逐一完成
Durability 持久性提交後永久保存當機也不遺失已提交資料

自我檢測

ACID 是什麼？
交易型資料庫的四大保證:原子性、一致性、隔離性、持久性,確保交易可靠。
ACID 和 BASE 差在哪？
ACID 強一致、重可靠(關聯式 DB);BASE 基本可用、最終一致、重擴展(NoSQL／分散式),用一致性換可用與規模。
為什麼分散式常選最終一致？
CAP 取捨下,分散式難同時滿足強一致與高可用;許多場景接受短暫不一致換取擴展性與低延遲。

🎯 重點整理

  1. ACID = 原子、一致、隔離、持久。
  2. 保障交易可靠(如金流)。
  3. BASE 用最終一致換可用與擴展。
  4. 分散式受 CAP 取捨,常選最終一致。
  5. 分析要懂資料來源的一致性保證。

📝 iPAS 考點提醒

ACID 與 Schema 是資料庫可靠性的基礎,iPAS 中級科目二考點。重點:ACID(原子性、一致性、隔離性、持久性)確保交易可靠;Schema 規範資料的結構與型別。易混點:關聯式資料庫重 ACID 與固定 schema(schema-on-write)、適合交易;NoSQL 常為效能與擴展放寬一致性(BASE)、用彈性 schema。情境:選資料庫時權衡一致性與擴展性。

❓ 常見問題

ACID 是什麼？

資料庫交易的四大保證：Atomicity 原子性、Consistency 一致性、Isolation 隔離性、Durability 持久性，確保交易可靠、資料正確。

四個性質逐一解釋？

原子性=交易全成或全敗；一致性=交易前後都符合規則；隔離性=並行交易互不干擾；持久性=提交後即使當機也不丟。

ACID 和 BASE 差在哪？

ACID 強一致(傳統關聯式 DB)；BASE(基本可用、軟狀態、最終一致)犧牲即時一致換高可用與擴展，常見於 NoSQL 與分散式。

為什麼分散式常選最終一致？

CAP 定理下，網路分區時無法同時兼顧一致性與可用性；大規模系統常選可用加最終一致，容忍短暫不一致。

資料分析為何要懂 ACID？

影響資料來源的可信與即時性；了解來源是強一致還是最終一致，才知道資料是否可能短暫不同步、影響分析正確性。
